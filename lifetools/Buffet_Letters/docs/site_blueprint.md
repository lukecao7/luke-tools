# 站点蓝图：Fork 索引层，重做 Deep Dive 层

## 核心判断

可以借鉴甚至 fork 现有网页的 `索引层`，但不要照搬它的 `公司页写法`。

更准确地说：

- `首页 / 公司索引 / 人物索引 / 概念索引 / 年份索引` 可以保留
- `公司详情页` 要从「百科页」改成「案例入口页 + 深度分析页」

这样既不会丢掉它已经做得很好的导航体验，也能把我们的差异化集中到最重要的地方。

## 什么适合 fork

下面这些很适合直接继承思路：

- 全局导航
- 公司、人物、概念三套索引
- 年份维度的信件入口
- 交叉链接体系
- 从信件到公司/人物/概念的反向链接

这些内容本质上是在解决“找得到”的问题。

## 什么必须重做

下面这些最好彻底换模型：

- 公司详情页
- 公司页里的“投资故事”
- 只列年份、不列证据的提及列表
- 不区分买入、持有、退出的叙述结构

这些内容本质上是在解决“看得深”的问题，而现有网页在这一层偏浅。

## 推荐的信息架构

### 1. 首页

首页负责告诉用户这个站点不是普通知识库，而是 `Buffett Investment Casebook`。

首页模块建议：

- 精选案例
- 最新补完案例
- 最经典的长期持有案例
- 已退出案例
- 危机反转案例
- 从年份进入、从公司进入、从概念进入

### 2. 公司页

公司页不要再承担全部分析，而是负责“分发”。

字段建议：

- 公司简介
- 在巴菲特体系中的角色
- 所属行业
- 首次出现年份
- 最近一次出现年份
- 相关案例列表
- 相关人物
- 相关概念
- 相关原始信件

一句话说，公司页回答的是：

`这家公司有哪些值得展开研究的 case？`

### 3. 案例页

案例页才是主战场。

建议 URL：

- `/cases/coca-cola-1988`
- `/cases/american-express-1994-1995`
- `/cases/goldman-sachs-2008-preferred`

案例页建议固定结构：

- `Summary`
- `Why Then`
- `Value At Entry`
- `Business Quality`
- `Timeline`
- `Evidence Ledger`
- `Exit Or Hold Logic`
- `Known Gaps`

### 4. 人物页

人物页可以基本沿用原网页思路，但多一个模块：

- 这个人物在哪些关键案例里扮演了决定性作用

例如：

- Roberto Goizueta 对可口可乐
- Ajit Jain 对保险 float
- Katharine Graham 对华盛顿邮报

### 5. 概念页

概念页也保留，但建议增加：

- 最能体现这个概念的代表案例

例如：

- `护城河` -> 可口可乐、美国运通
- `危机中的品牌韧性` -> 美国运通
- `不卖逻辑` -> 可口可乐、美国运通

## 推荐路由设计

```text
/
/letters
/letters/1988
/companies
/companies/coca-cola
/people
/people/charlie-munger
/concepts
/concepts/intrinsic-value
/cases
/cases/coca-cola-1988
/cases/american-express-1994-1995
```

## 推荐数据模型

站点至少拆成三层数据：

- `companies`
- `cases`
- `citations`

关系是：

- 一个 `company` 可以有多个 `case`
- 一个 `case` 可以有多条 `citation`
- 一个 `citation` 绑定到具体 `year + page`

## 页面职责边界

### 公司页负责：

- 汇总
- 分发
- 建立上下文

### 案例页负责：

- 论证
- 比较
- 引用原文
- 给出买入与持有/退出逻辑

## 首页文案的定位建议

不要叫“巴菲特知识库”，那会天然把用户预期带到百科站。

更好的定位文案：

- 巴菲特投资案例库
- Buffett Investment Casebook
- 从股东信到投资决策的研究站

## 第一阶段最值得上线的页面

先不要追求全。

先做：

- 公司索引
- 人物索引
- 概念索引
- 可口可乐案例
- 美国运通案例
- 华盛顿邮报案例
- 盖可保险案例

这 4 个案例就足够把站点气质从“知识整理”拉到“案例研究”。

## 产品上的一句话原则

`索引层解决 coverage，案例层解决 depth。`
