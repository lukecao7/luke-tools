# OCR 与划线修复

本轮针对用户反馈的“识别不准、划线选取不准”，完成本机版修复。译文恢复原版排版仍是下一项工作，本轮没有调整该视觉方案或发布线上版本。

## 原因

现有 40 页调查报告的 2193 个文字片段全部来自 PDF 自带的文字层，OCR 使用次数为零。因此，这份材料里的划线问题不能全部归因于 OCR。

检查及复现确定了四个问题：

1. PDF 可选文字层缺少页面缩放值，字体尺寸回退成界面的 16px，与 PDF 原页的文字不一致。已补齐缩放值，并用 PDF 坐标独立核对文字层宽度。
2. 选区依靠搜索文字定位；同页两处“36%”，选第二处却保存到第一处。已改为根据实际选中的文字节点与原文字符范围定位。
3. 拖动高亮边界按平均字宽估算位置。已改为测量真实字符边界，并缓存坐标以避免拖动时反复测量整段。
4. 扫描页虽有后端 OCR 结果，前端没有可供选取的 OCR 文字层。已用识别坐标补上，支持原页划取和高亮。

同时保留了原生文字中的内部空格及原始字符偏移，支持同页跨文字块一次保存高亮；新增了对明显乱码文字层的 OCR 回退判断。识别不到可读文字时，提示检查页面清晰度。

## OCR 选择

| 方案 | 本次判断 |
|---|---|
| Tesseract.js | 现有方案，本身没有按页 API 费用，仍保留为兼容选项。样本图表的横条和部分百分比被识别成乱码。 |
| RapidOCR / PaddleOCR | 选择用于当前本机版。RapidOCR 是基于 PaddleOCR 模型的开源部署工具，支持本地运行和字符坐标；本机已安装并实测。固定版本为 RapidOCR 3.9.2、ONNX Runtime 1.29.0，使用 PP-OCRv6-small。 |
| DeepSeek OCR 2 | 查阅了官方项目，没有在本机实测。官方部署示例依赖 CUDA、PyTorch 和 GPU 推理，因此本轮没有作为这台 Mac 的默认方案。不能把这一部署判断理解为识别质量不如 RapidOCR。 |
| MinerU | 查阅了官方项目，没有实测。具备更完整的文档结构解析能力，也支持 CPU/Mac，但官方完整部署所列的依赖与存储要求更大；当前先解决选区定位及扫描识字。 |

来源：[RapidOCR 项目](https://github.com/RapidAI/RapidOCR)、[坐标输出文档](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/)、[PaddleOCR 项目](https://github.com/PaddlePaddle/PaddleOCR)、[DeepSeek OCR 2 官方部署](https://github.com/deepseek-ai/DeepSeek-OCR-2)、[MinerU 官方项目](https://github.com/opendatalab/MinerU)。以上为 2026-09-05 查阅结果。

## 本机样本结果

把现有报告的 PDF 第 7、8 页按相同分辨率渲染成图片，再分别交给两套 OCR。以原生 PDF 中的文字及位置作为参照，检查两页的 13 处独立图表百分比。

| 检查 | Tesseract | 最终配置的 RapidOCR |
|---|---|---|
| 13 处百分比的文字与位置匹配 | 5 / 13 | 13 / 13 |
| 第 7 页识别耗时 | 1.81 秒 | 1.86 秒 |
| 第 8 页识别耗时 | 2.46 秒 | 1.52 秒 |

这是两页指定数字位置的检查，不是通用 OCR 准确率或完整性能基准。耗时未包括程序首次初始化。RapidOCR 默认的行方向分类曾把“69%”错误翻转；当前配置关闭该分类，PDF 页面的旋转由渲染器处理。倒置扫描文字、复杂旋转文字和低清晰度材料仍需另测。

新增的中英文图片型 PDF 样本也实际跑过 OCR，“调查显示，75%的企业受到关税影响。”及英文句子识别通过，浏览器可在原页选中“75%”并保存、重新打开高亮。

验证通过：语法检查、版面与分段测试、浏览器中的重复文字选取、真实鼠标拖动、缩放前后宽度与位置、跨文字块高亮、中英文扫描件、重新打开高亮，以及现有 40 页报告回归。浏览器测试里的任务修改保存在隔离的内存副本中；另用隔离服务验证了跨块高亮确实写入存储，非法批次不会留下部分修改。未改动用户原有阅读数据。

证据保存在 `.runtime/ocr-fix-2026-09-05/`：`benchmark-final.json`、`selection-tests.json`、`highlight-api-test.json`，以及修复前后截图和源文件备份。

## 运行与范围

当前这台 Mac 已安装本地 OCR 环境。启动本机服务后，新导入的扫描页会自动使用 RapidOCR；正常数字 PDF 继续读取原生文字，不增加一次 OCR。

其他本机环境初始化：

```sh
npm run setup:ocr
npm start
```

需要 Python 环境管理工具 `uv`。本机 OCR 环境约占 285MB 磁盘，无按页 API 费用；翻译、解释和摘要仍由原有 AI 服务承担，相关成本不因这次改动消失。

`OCR_ENGINE=auto` 在已安装本地环境时选择 RapidOCR。可以通过 `OCR_ENGINE=rapidocr` 或 `OCR_ENGINE=tesseract` 明确指定，也可以用 `OCR_PYTHON` 指定已有 Python 环境。Vercel 的自动模式仍使用现有 Tesseract 路径；本轮没有把 Python OCR 部署到线上。新任务会记录每页的识别引擎和触发原因。

旧扫描任务若需要改善已经识错的文字，须重新导入；本次没有自动重写旧原文、翻译或高亮。
